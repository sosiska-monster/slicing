# Архитектура и команды

- `src/slicing/__main__.py`: подготовка VOD или независимый `--edit-plan`, без PostgreSQL для рендера.
- `twitch.py`, `pipeline.py`, `db.py`: поиск/подготовка публичного архива, состояния downloaded и исторические исключения.
- `media.py`: FFmpeg/FFprobe, Whisper, проверка установленного инструментария.
- `render_plan.py`: схема v1, интервалы, crop/place, ASS, склейка звука, H.264/AAC, манифест.
- `framing.py`: вычисление компоновки по размеченным областям, полезным второстепенным объектам, UI и говорящему. Старые явные панели обходят автоматический расчёт.
- `.agents/skills/slicing-editor/`: ручной редакторский workflow, явный вызов. Не фоновая автоматизация.
- `tests/`: регрессии рендера/компоновки, выбор VOD, отдельная интеграция PostgreSQL.

## Разделение решений

Редактор: источник/интервалы, порядок, хук, развязка, герой, важные области, спорный текст и причина резерва.
Python/FFmpeg/Whisper: получение и перенос временных меток, кропы, масштабирование, маски, ASS, сборка и техническая проверка. Повторный рендер не вызывает редактора.

```powershell
# После установки зависимостей из pyproject.toml; FFmpeg с libass/libx264/AAC должен быть установлен отдельно.
$env:SLICING_FFMPEG = 'C:\path\to\ffmpeg.exe'
python -B -m slicing --edit-plan <absolute-plan.json> --clip <ID>
python -B -m slicing --edit-plan <absolute-plan.json> --clip <ID> --draft-subtitles
python -B -m unittest discover -s tests -v
```

Штатный CLI считает cwd рабочим корнем. Для HQ перейдите в `data/review/codex_pilot/full_hq/`; пакет slicing должен быть установлен в используемом окружении. `source.file` должен быть `data/vods/<id>.mp4` относительно этого корня. Прямой API `render_plan(..., work_directory=...)` позволяет держать временные файлы в разрешённом каталоге. CLI по умолчанию создаёт временную папку рядом с выходом — учитывайте ограничения записи конкретной задачи.

## Координаты и звук

`start_ms/end_ms` и ручные `captions` — миллисекунды воспроизведения исходного VOD. Массив segments задаёт порядок. Метки `subtitle_review` — шкала уже склеенного клипа, со стабильными ID, segment и SHA-256. Эти системы не взаимозаменяемы без пересчёта.

crop = [x,y,w,h] в исходнике; place и masks — сетка 720×1280; export_size масштабирует выход. Координаты и размеры кропов чётные, чтобы не нарушать сетку 4:2:0. Для сохранения пропорций подбирайте crop с соответствующим отношением сторон. Старый ручной renderer масштабирует crop непосредственно в place: неправильные пропорции в данных могут растянуть объект.

При правке картинки можно скопировать прежнюю AAC после нового видеорендера; подтвердить payload/PTS/padding и PCM, записать происхождение в manifest. Сам stock render по умолчанию вновь готовит звук по исходным интервалам. Новое поле «approved_audio_parent» в batch-индексе обрабатывается вспомогательными скриптами, а не универсальным CLI.

## Проверка и повтор

Декодирование всего MP4; FFprobe, 9:16, SAR, длительность и звук; реальные bbox libass с обводкой; полный объект/движение; UI TikTok и Shorts отдельно; маски на всём интервале рекламы. История проверок должна указывать число кадров, временное покрытие и наличие слуховой оценки.

Batch helpers лежат локально в data/review/batch/2876630043/scripts. Снимок в project_context дан для чтения; сначала восстановите исходную структуру, проверьте пути и хеши. Некоторые одноразовые polish/refine helpers не идемпотентны — не запускайте их все подряд. `resume.py --verify-only` проверяет существующий запуск; без медиа из data этот сценарий не воспроизводится.
