## Вход и повторная сборка

Планы версии 1 с явным `framing.panels` используют прежний путь. Для нового режима добавьте `auto_layout` на уровне документа. В нём нужны `kind`, `source`, `reference_size_px` и профили `TikTok` и `Shorts` из примеров. Координаты UI переводятся в фактическое разрешение с учётом ступеньки под кнопки. Поля `editorial` фиксируют хук и развязку для проверки. Порядок и длительность определяет список `segments`.

В каждой новой сцене `framing.regions` содержит именованные области с приоритетом `required` или `secondary`. Первая обязательная область задаёт акцент. Прямоугольники `[x, y, w, h]` размечаются на исходнике. Для неподвижной области подходит `box`. Для движущейся области используйте `track` без разрывов. Каждый его прямоугольник покрывает всё движение внутри собственного полуоткрытого интервала VOD. Необязательный `viewport` ограничивает допустимую область камеры или табло в исходнике.

Код сначала пробует один портретный кроп, затем две панели с горизонтальным или вертикальным разделителем. Титры проверяются по границам libass с обводкой. При конфликте пробуются другие позиции внутри сцены. Для локальной повторной сборки используются сохранённые `subtitle_review` или заданные `captions`. Контрольный план с краем объекта за пределами доступного кропа вернул `needs_review` с исходным интервалом и объектом. Команда завершилась с кодом 1, MP4 для этого случая не создан.

Пример штатной команды из корня HQ для запуска в рабочей копии со свободным каталогом результата.

```powershell
python -m slicing --edit-plan data/review/auto_layout/AUTO_PHONE/edit_plan.json --clip AUTO_PHONE
```

## Проверки

- Три мастера и обзор полностью декодированы. FFprobe подтвердил H.264, AAC 48 кГц и 1080 × 1920 при 30 кадрах/с. В обзоре подряд 526 кадров трёх мастеров, длительность 17,568 с.
- На 291 кадре с активными титрами измерены фактические границы ASS. Пересечений титров с обязательными областями и UI не найдено. Профили обычной ленты Krumzi дают расчётную оценку. Мобильный предпросмотр не проводился. [Таблица Krumzi](https://www.krumzi.com/tools/safe-zone-checker)
- Для телефона сопоставлены пиксели каждого выходного кадра с HQ и отдельно измерена светящаяся часть дисплея. Все измерения остались внутри размеченной траектории. В некоторых кадрах экран вплотную подходит к исходной границе камеры. Верхний кроп сохраняет видимые пиксели до этой границы.
- Для ускорения локальных прогонов использована временная индексированная копия HQ без перекодирования. На всех отрезках трёх примеров и старого плана совпали 3 465 пакетов видео и звука, PTS и DTS совпали. Временная копия удалена после проверки.
- Старый план `PUB_17d_ui` пересобран штатной командой. Графы FFmpeg и ASS совпали со снимком кода, SHA‑256 нового MP4 совпал с уже сохранённым MP4. Повторный прогон `AUTO_PHONE` дал те же SHA‑256 для MP4, ASS и манифеста.
- Девять тестов прошли, включая регрессию обрезанного края при видимом центре. Интеграционный тест PostgreSQL пропущен, поскольку требуется отдельная тестовая база. В Git нет HEAD. Diff сделан относительно снимка `before/` и проверен командой `git apply --reverse --check`.
